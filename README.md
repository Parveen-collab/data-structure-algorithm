# 📖 Overview

This repository documents my journey of learning **Data Structures and Algorithms (DSA)** using **JavaScript**.

The primary goal is to build a strong understanding of fundamental data structures and algorithms by implementing them from scratch while learning the intuition behind each concept.

Unlike many DSA repositories that only contain code, this repository combines:

- ✅ JavaScript implementations
- ✅ Theory and explanations
- ✅ Visual diagrams and screenshots
- ✅ Learning roadmap
- ✅ Interview preparation
- ✅ LeetCode-focused concepts

The visual references included in this repository help simplify difficult topics that are often challenging to understand through code alone.

Whether you're preparing for coding interviews, improving problem-solving skills, or learning computer science fundamentals, this repository is designed to be a practical learning companion.

# ⏱️ Time Complexity Cheat Sheet

Understanding time complexity is essential for writing efficient algorithms.

| Operation / Algorithm | Best | Average | Worst |
|-----------------------|:----:|:-------:|:-----:|
| Linear Search | O(1) | O(n) | O(n) |
| Binary Search | O(1) | O(log n) | O(log n) |
| Bubble Sort | O(n) | O(n²) | O(n²) |
| Insertion Sort | O(n) | O(n²) | O(n²) |
| Merge Sort | O(n log n) | O(n log n) | O(n log n) |
| Quick Sort | O(n log n) | O(n log n) | O(n²) |
| Heap Sort | O(n log n) | O(n log n) | O(n log n) |

---

## 📌 Common Data Structure Complexities

| Data Structure | Access | Search | Insert | Delete |
|---------------|:------:|:------:|:------:|:------:|
| Array | O(1) | O(n) | O(n) | O(n) |
| Linked List | O(n) | O(n) | O(1) | O(1) |
| Stack | O(n) | O(n) | O(1) | O(1) |
| Queue | O(n) | O(n) | O(1) | O(1) |
| HashMap | - | O(1)* | O(1)* | O(1)* |
| Binary Search Tree | O(log n) | O(log n) | O(log n) | O(log n) |
| Heap | - | O(n) | O(log n) | O(log n) |

> **Note:** `*` Average-case complexity. Worst-case complexity depends on implementation and collision handling.

# 📖 Repository Philosophy

This repository is built on one simple principle:

> **Understanding is more important than memorization.**

Instead of simply collecting solutions, every topic should answer the following questions:

- ✅ What problem does this solve?
- ✅ Why does this algorithm work?
- ✅ What is the intuition behind it?
- ✅ What is its time complexity?
- ✅ What is its space complexity?
- ✅ Where is it used?
- ✅ Which interview questions use this concept?

The objective is to become a better problem solver rather than memorizing patterns.
